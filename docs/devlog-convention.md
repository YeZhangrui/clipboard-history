# 开发日志书写规范

> 文档编号：DEVLOG-001　|　版本：v1.0　|　状态：已定稿（2026-09-07）

## 1. 总原则

- **每天一个文件**：`devlogs/YYYY-MM-DD.md`（如 `devlogs/2026-09-07.md`），用当天日期命名。
- **自动记录机制**：每个开发会话/阶段结束时，由 AI 自动更新当日日志（写完成 + 待办），
  无需用户手动操作；用户每天的对话需求也会被记录进去。
- **日志永不删除**：历史日志只增不改（可追加勘误），保证全程可追溯。

## 2. 文件模板

```markdown
# 开发日志 — YYYY-MM-DD

## 今日任务
（本日/本会话的目标）

## ✅ 完成事项
- [ ] 事项 1（对应阶段/编号）
- [ ] 事项 2

## 🔜 待办事项
- [ ] 未完成或下一步的事项（含下一阶段任务）

## 🐞 问题与决策
- 问题：……
- 决策：……（说明原因）

## 📋 用户反馈
（用户今天提的需求/疑问/确认，例如"确认存储天数 1/3/5 天"）

## 明日计划
（下一会话开始时的第一步，供直接接续）
```

## 3. 更新规则

| 时机 | 必写内容 |
|---|---|
| 会话开始（首次） | 新建当日文件（若不存在），填"今日任务" |
| 每个阶段结束 | "完成事项" + "问题与决策" + "明日计划" |
| 用户提出新需求 | 记录到"用户反馈" |
| 当日下午 | 若有"待办事项"未清，保留并在次日继续 |

## 4. 命名与回溯

- 文件名过长的日志可归档为 `devlogs/archive/YYYY-MM-DD.md`（当月结束后）。
- 搜索：按日期或关键词用"日志索引"（`devlogs/README.md` 中的文件列表）回溯。
