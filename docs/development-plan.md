## 2. 每阶段的执行流程（固定 SOP）

1. **开工前**：读取 `docs/development-plan.md` 确认本阶段任务清单；
   读取当日日志（`devlogs/YYYY-MM-DD.md`，不存在则按 `docs/devlog-convention.md` 新建）。
2. **开发**：只做本阶段任务，不做下一阶段的事；每个小步保持程序可运行。
3. **自检**：按本阶段"验收标准"逐项自测；发现 BUG 必须修复后才能结束阶段。
4. **写日志**：更新当日日志：完成事项、待办事项、问题与决策。
5. **汇报**：向用户说明"这阶段做了什么、怎么验证、下一步是什么"，
   用户确认后再进入下一阶段。

## 3. 质量门禁（每阶段必须全部满足）

- [ ] 程序无未修复的崩溃/报错（异常只记日志不崩）
- [ ] 本阶段验收标准全部通过
- [ ] 当日开发日志已更新（完成 + 待办）
- [ ] 优先级的 P0 需求在本阶段范围内全部落实
- [ ] 未引入下一阶段才该有的复杂功能（防止过度开发）
- [ ] **UI 易读性（用户 2026-09-07 要求，纳入长期标准）**：任何 UI 改动后必须
      渲染实际截图并检查——文字颜色与底色对比清晰（所有控件文字显式指定颜色，
      不依赖系统深色/浅色调色板），检查项含：主窗口、下拉框（含展开态）、
      确认对话框、搜索框 placeholder/输入、状态栏；必要时做像素级颜色验证
      （最深色像素应达到 #1F2937 级别的深色或设计规范指定色）
- [ ] **UI 一致性（用户 2026-09-07 要求，v1.12 起纳入）**：同组控件（按钮组等）必须
      几何完全一致——打印/断言各控件 geometry（宽高相同、间距相同）+ 截图目检
      圆角曲率与大小，通过后方可打包提交

## 4. 阶段 1 详细任务（下一个阶段，供开工时参考）

**目标**：最小可运行的剪贴板监听（仅文本），验证"复制 → 入库"链路。

1. 搭建 `src/` 骨架：`main.py`、`config.py`、`database.py`、`clipboard_watcher.py`。
2. `database.py`：建表 `clipboard_items`（含全部字段，图片字段先置空）+ 插入/查询接口。
3. `clipboard_watcher.py`：监听 `dataChanged`，文本内容入库（`type='text'`）。
4. `main.py`：启动监听 + 命令行 `--dump` 参数打印最近 10 条记录，供人工验证。
5. 验收：运行程序后复制 3 段文字，`--dump` 能看到 3 条记录；再复制同一段文字，记录合并为 1 条。

> ⚠️ 阶段 1 不做 UI、不做托盘、不做开机自启，这些留给阶段 3/4。
