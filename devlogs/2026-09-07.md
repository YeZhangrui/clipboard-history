## 🐞 问题与决策
- 存储天数范围：用户确认 1/3/5 天；自定义天数（7/30/永久）列为扩展项（`docs/requirements.md` 第 5 节）
- 技术选型：选择 Python + PySide6 而非 Electron/C#，理由见 `docs/technology.md` 第 1 节（监听图片双类型支持好、单文件打包成熟）
- BUG 修复：Windows 控制台默认 GBK 编码，打印 ✓ 等符号导致 UnicodeEncodeError → 输出改编码安全符号 + stdout/stderr 编码兜底
- BUG 修复：时间戳精度仅到秒，1 秒内连续复制导致排序不稳定 → 阶段 1 改毫秒；阶段 2 自测发现毫秒仍可碰撞 → 最终提升为**微秒**精度 + ORDER BY id DESC 次级排序；自测按真实复制间隔（10ms）模拟
- BUG 修复：重写 `image_store.py` 时丢失 `get_images_dir()` 调用，`images/` 目录未创建导致图片静默保存失败 → 补回并改为保存失败抛异常（不再静默）
- BUG 修复：`QLabel.alignment()` 返回的 AlignmentFlag 无 `setFlag` 方法（PySide6 6.11）→ 改用 `AlignHCenter | AlignVCenter` 组合
- ⚠️ 事故：`--self-test` 自阶段 1 起使用真实数据库（当时无用户数据，未暴露）；阶段 3 用户记录 4 条被回归测试清空 → 立即修复为临时数据库，并加测试前后数据校验；向用户说明并致歉
- 决策：图片指纹从"PNG 编码字节"改为"归一化 ARGB32 像素"——同像素不同编码/解码来源一律合并，解决用户看到的重复记录；旧记录 hash 方式不复用（一次性，可接受）
- 决策：**文本优先**策略——Word/Excel 复制文字时剪贴板同时带位图，应记录为文本而非图片（见 `clipboard_watcher.py` 注释）
- 决策：图片指纹 = PNG 编码字节的 sha256（同像素同指纹，编码确定性）→（已被上面像素归一化方案取代）
- 决策：UI 搜索/刷新均使用防抖（300ms 搜索、200ms 列表刷新），避免高频输入/连续复制时重复重建列表
- 观察：Qt 应用向剪贴板写入时（setText/setImage），另一 Qt 监听进程收不到 dataChanged（OLE 延迟渲染广播差异）；标准 Win32/.NET API 写入（PowerShell、System.Windows.Forms.Clipboard）可正常捕获 → 真实用户场景（浏览器/Office/微信）不受影响，仅为测试工具限制，已记录
- 观察：Windows 剪贴板单次写入会触发 2 次 dataChanged（间隔 ~2ms），去重合并机制正确兜底（首次插入、后续合并）
